# Одна реализация

## Решение

Все хосты используют одну реализацию на C++. Различия хостов скрыты за узкими интерфейсами: `src/app/os/` для файлов, сети, процессов и томов, `src/app/runtime/session_*_posix`, `session_*_windows`, `session_macos` и `session_linux` для частей сеанса, которые обращаются к Android и QNX по-разному, например канала управления, транспорта Android и канала QMP, и `src/app/platform/window_shell_*` для окна. Каждый хост компилирует только свои файлы бэкенда.

## Контекст

Voyemu работает на macOS, Windows и Linux. Каждая возможность описывается один раз для всех платформ, поэтому её поведение не должно зависеть от хоста сверх того, что навязывает операционная система.

## Альтернативы

**Отдельная реализация каждой возможности для каждого хоста.** Поведение расходится, тест на одном хосте ничего не говорит о другом, каждое исправление делается дважды.

**Ветки препроцессора внутри кода возможностей.** Различия хостов расползаются по многим файлам и не видны тому, кто читает код одного хоста.

## Аргумент

Тесты общего кода запускаются на любом хосте, включая Linux в CI, и покрывают поведение каждого хоста. Файл бэкенда короткий и перечисляет ровно то, чем отличаются хосты. Новому хосту нужны новые файлы бэкенда, а не правки по всему коду возможностей.

## Последствия

Новое поведение, зависящее от хоста, оформляется функцией в `os/`, бэкендом сеанса или бэкендом оболочки, а не веткой в коде возможности. У Linux свои бэкенды; см. [Linux x64 как хост](linux-target.ru.md). [Окно SDL3](sdl3-window.ru.md) следует тому же правилу.
