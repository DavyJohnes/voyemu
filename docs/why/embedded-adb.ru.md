# Встроенный ADB

## Решение

Во время сеанса супервизор обращается к гостю Android через встроенный клиент ADB. Клиент подключается через петлевой интерфейс (loopback) к порту `adbd` того эмулятора, который запустил сеанс, без внешнего сервера ADB. Клиент — код Voyemu в `src/app/adb/` поверх закреплённых исходников ADB из AOSP в `src/app/third_party/aosp_adb/`. Подготовка машины и импорт с физического автомобиля по-прежнему используют закреплённый `adb` из SDK.

## Контекст

Стандартный ADB проводит каждую команду через один сервер ADB на пользователя на порту 5037, общий для всех инструментов хоста. Любой инструмент может перезапустить этот сервер, а сервер подключается к каждому найденному эмулятору. Voyemu должен доказать, что управляемый гость принадлежит его сеансу: он проверяет сохранённый процесс эмулятора вместе с его консолью и слушателями `adbd`. Эмулятор из SDK к тому же пытается уведомить сервер ADB хоста.

## Альтернативы

**Закреплённый `adb` из SDK с сервером по умолчанию.** Сервер — глобальное состояние: IDE или другой инструмент может перезапустить его или подключить тот же эмулятор, и сеанс не может доказать, каким транспортом владеет.

**`adb` из SDK с отдельным портом сервера на сеанс.** Общий доступ исчезает, но остаётся отдельный процесс сервера со своим временем жизни, переподключением и сканированием портов, а каждая команда запускает ещё один процесс клиента.

## Аргумент

Транспорт живёт внутри супервизора, который владеет сеансом. Время жизни транспорта совпадает с сеансом, переподключение после перезагрузки гостя остаётся под контролем супервизора, и никакой другой процесс не может его перехватить. Voyemu занимает порт уведомления сервера, не принимая на нём соединений, поэтому внешний сервер не может занять и этот порт. Один и тот же нативный код собирается на каждом хосте и не требует ни внешнего ADB, ни другой среды выполнения.

## Последствия

Встроенный клиент работает с одним локальным эмулятором на процесс и не содержит транспорта USB; физические устройства подключаются через `adb` из SDK. Клиент не хранит ключ ADB: закреплённые системные образы эмулятора запускают `adbd` с `ro.adb.secure=0`, а гость, запросивший аутентификацию, остаётся неавторизованным. Обновление ADB — обновление исходников AOSP; CMake проверяет размеры и SHA-256 неизменённых файлов перед сборкой, а изменённые файлы указывают исходную ревизию AOSP; см. [пины](pins.ru.md). Страница [Встроенный ADB](../how/embedded-adb.ru.md) описывает, как сеанс использует клиент.
