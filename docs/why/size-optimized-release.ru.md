# Release с оптимизацией размера

## Решение

Release компилирует лаунчер с `-Os` и помещает каждую функцию и каждый объект данных в свою секцию; исходники покадрового пути окна компилируются с `-O2`. Оптимизация при компоновке выключена. Флаги и покадровые исходники названы на странице [Сборка](../dev/build.ru.md#оптимизация).

## Контекст

Лаунчер — один статический исполняемый файл с CLI, подготовкой, Voyemu API, окном и графическим обработчиком. Большая часть его кода выполняется один раз за команду или ждёт ввода-вывода, подготовки на Java и гостей, которых исполняют QEMU и эмулятор. На каждом кадре, до 60 кадров в секунду, лаунчер преобразует кадры QNX, принимает кадры Android, декодирует кадры PNG загрузочной анимации и стартовых роликов, а в графическом обработчике воспроизводит рисование QNX через ANGLE. Проверки пинов считают SHA-256 командами процессора, где они есть, поэтому их скорость почти не зависит от уровня оптимизации.

## Альтернативы

**`-O3` везде** — умолчание CMake для Release. Самый большой исполняемый файл; выигрыш в скорости достаётся коду, который ждёт.

**`-Os` везде.** Самый маленький исполняемый файл, но преобразование кадра QNX идёт примерно вдвое дольше, а это заметно в бюджете кадра 16,7 мс.

**`-O2` с секциями везде.** Экономит около четверти того, что экономит `-Os`.

**ThinLTO.** Поверх `-Os` экономит на Linux ещё 3 %. Компоновщик Mach-O из Zig отказывается от оптимизации при компоновке, поэтому macOS собиралась бы иначе, чем Windows и Linux. Каждый исполняемый файл тестов компоновался бы через LTO, а параметра, ограничивающего потоки LTO в ld.lld, Zig не передаёт.

**Слияние одинакового кода в ld.lld.** Zig 0.15.2 отклоняет `--icf` среди параметров компоновщика. Команда компоновки в обход Zig повторила бы то, что Zig выводит для каждой цели: стартовые файлы, среды выполнения C и C++ и заглушки libc.

## Аргумент

Размер экономится там, где скорость не важна, а скорость сохраняется там, где идут кадры. Покадровый список короткий и называет исходники, поэтому его изменение видно при ревью.

## Последствия

Каждый исходник с покадрового пути окна входит в `voyemu_frame_path_sources` в `src/app/CMakeLists.txt` или в его фильтр SDL3. Подготовка идёт немного медленнее, чем с `-O3`. На Windows lld-link сливает одинаковые функции по своему умолчанию; Linux и macOS обходятся без слияния, пока Zig не передаёт такой параметр. Флаги входят в [набор инструментов Zig](zig-toolchain.ru.md) и в решение [Только Release](release-only.ru.md).
