# Только Ninja

## Решение

Voyemu настраивается только с генератором Ninja; с любым другим генератором CMake останавливается с ошибкой. Ninja закреплён в `src/app/toolchain.json` для каждого хоста.

## Контекст

Код хоста собирается на macOS, Windows и Linux [набором инструментов Zig](zig-toolchain.ru.md). clang-tidy читает `compile_commands.json`, а CI и локальная сборка должны выполнять одни и те же команды.

## Альтернативы

**Генераторы Visual Studio и Xcode.** Они привязаны к MSVC и Xcode, которые заменяет набор инструментов Zig, и не создают `compile_commands.json`.

**Unix Makefiles.** На Windows нет нативного `make`, а второй генератор удваивает число конфигураций, которые нужно поддерживать.

**Любой генератор на выбор пользователя.** Каждому нужно своё тестирование, и каждый по-своему отслеживает зависимости и выполняет пользовательские команды.

## Аргумент

Один небольшой закреплённый исполняемый файл ведёт себя одинаково на каждом хосте и по умолчанию собирает параллельно. Один генератор — один набор файлов сборки, о котором нужно думать в CI и локально. Он же создаёт базу компиляции, которая нужна clang-tidy.

## Последствия

`cmake` и `ninja` должны быть в `PATH`; при настройке передаётся `-G Ninja`. Переход с другого генератора требует нового каталога сборки. Пользовательские цели `format-check`, `tidy-check` и `errorprone-check` работают одинаково везде. Страница [Сборка](../dev/build.ru.md) приводит команды настройки и сборки.
