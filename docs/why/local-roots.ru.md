# Четыре корня `.local`

## Решение

Локальное состояние лежит ровно в четырёх корнях внутри `.local/`: `profiles` для оригиналов и общих неизменяемых входов подготовки, `toolchains` для установленных инструментов и загрузок, `build` для воспроизводимых результатов и временных заданий и `machines/<name>` для временного состояния каждой машины. Постоянные диски гостей и установленные данные остаются в `machines/<name>/` вне `.local/`.

## Контекст

Voyemu работает с данными разного срока жизни и владельцев: прошивкой, которую импортирует пользователь, закреплёнными инструментами, пересобираемыми результатами, состоянием запуска и дисками гостей с установленными приложениями. Если их смешать, непонятно, что можно удалить, разделить или скопировать.

## Альтернативы

**Один каталог кеша для всего.** Удаление кеша ради места может стереть оригиналы или состояние работающего сеанса.

**Каталоги, которые выбирает каждый инструмент.** Инструменты, загрузки и результаты расползаются по проекту и домашнему каталогу пользователя.

## Аргумент

У каждого корня одно правило. `build` можно удалить и пересобрать. `toolchains` хранит одну каноническую копию каждого закреплённого инструмента для всех машин. `profiles` хранит входы, которые не меняются после импорта. `.local/machines/<name>` создаётся заново, если его нет, поэтому в копию машины не попадает устаревшее состояние сеанса.

## Последствия

Копия `machines/<name>/` сохраняет установленные данные без `.local/machines/`; Voyemu создаёт это состояние заново и, если снимков RAM нет, запускает гостей холодным стартом. Отдельные задания используют общие неизменяемые входы и создают только записываемые слои, а не копируют деревья SDK или проекта. Что содержит машина, описано в записи о [профилях и машинах](profiles-machines.ru.md). Страница [Корни `.local`](../how/local-roots.ru.md) перечисляет содержимое корней и когда их можно удалять.
