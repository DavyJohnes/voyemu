# C++ для хоста

## Решение

Хост Voyemu написан на C++20, а код, который работает внутри гостя QNX, — на C11. Подготовка APK и DEX работает на [Java](java-preparation.ru.md). Rust не используется.

## Контекст

Лаунчер собирает сторонний код на C и C++ из закреплённых исходников: SDL3 с его stb_image, Dear ImGui, nlohmann/json, miniz, lzokay и исходники AOSP протокола ADB хоста в `src/app/third_party/aosp_adb/`, на которых построен [встроенный ADB](embedded-adb.ru.md). Помощники e2fsprogs для образов — программы на C поверх libext2fs из закреплённого релиза e2fsprogs. Движок QNX — QEMU с патчем его исходников на C, `src/app/qnx-host.patch`. Интерфейсы хоста, которые вызывает лаунчер, написаны на C, Objective-C и COM: Cocoa и VideoToolbox на macOS, Win32 и Media Foundation на Windows.

Код из `src/guest/qnx/` работает внутри штатных образов QNX 7.0 на aarch64. Подготовка компилирует его компилятором clang из закреплённого Zig для цели `aarch64-unknown-qnx7.0.0` без QNX SDP: объектные файлы видят только компилятор и подготовленные заголовки, а библиотеки компонуются с заглушками, в которых есть только имена `libc.so.4` и `libscreen.so.1` гостя (soname). Подготовка проверяет, что гостевые двоичные файлы не превышают своих пределов в байтах. Хост и гость разделяют структуры обмена: хост включает заголовок на C `src/guest/qnx/cluster_ui_wire.h` и проверяет его размеры и смещения через `static_assert`, а тесты хоста компилируют исходники гостя на C напрямую.

Rust поддерживает QNX SDP 7.0 на aarch64 целью `aarch64-unknown-nto-qnx700` уровня 3 (tier 3). Его [страница поддержки платформ](https://doc.rust-lang.org/rustc/platform-support/nto-qnx.html) отмечает полную стандартную библиотеку для этой цели как незавершённую; работает только `no_std`. Готовых сборок для цели Rust не поставляет, а для компоновки сборка вызывает `qcc` из установленного QNX SDP.

## Альтернативы

**Хост на Rust с привязками.** SDL3, Dear ImGui, коду AOSP ADB, libext2fs и интерфейсам хоста нужны привязки (bindings); для интерфейсов Dear ImGui и AOSP ADB на C++ сначала нужна обёртка на C. Каждый вызов через привязку — `unsafe`, поэтому граница с этими библиотеками сохраняет риски C. Существующий хост пришлось бы переписать. Rust приносит свой компилятор и Cargo — второй набор инструментов для закрепления на каждом хосте рядом с Zig, который всё равно собирает код гостя и помощников.

**Rust для кода гостя QNX.** Единственная цель QNX 7.0 для aarch64 — уровня 3 с `no_std`, и ей нужны QNX SDP и `qcc`, без которых Voyemu обходится. Структуры обмена существовали бы дважды: на C для хоста и на Rust для гостя.

**Смешанный хост на C++ и Rust.** Два компилятора, сборка Cargo внутри CMake для трёх целей и интерфейс на C между половинами. clang-tidy проверяет только половину на C++, и половине на Rust нужны свои проверки.

**Go.** Каждая библиотека на C идёт через cgo, а Dear ImGui и AOSP ADB ещё и через обёртку на C. Go добавляет среду выполнения со сборкой мусора и второй набор инструментов. Порта Go для QNX нет, поэтому код гостя остаётся на C.

## Аргумент

Библиотеки, интерфейсы хоста и гость написаны на C и C++, поэтому C++ вызывает их без привязок, а хост и гость разделяют заголовки на C как есть. Один [набор инструментов Zig](zig-toolchain.ru.md) собирает лаунчер, код гостя QNX и помощники e2fsprogs для macOS, Windows и Linux; Rust добавил бы набор инструментов и ни одного не убрал бы.

Против ошибок памяти C и C++ работают проверки:

- clang-tidy запускает группу `bugprone` с предупреждениями как ошибками на каждом исходнике Voyemu на C, C++ и Objective-C++ — в CI на дереве Linux и на дереве кросс-сборки для Windows; см. [проверки](../dev/checks.ru.md).
- Основные библиотеки лаунчера компилируются с `-Wall -Wextra -Wpedantic`, а код гостя — с `-Wall -Werror`.
- Исполняемые файлы тестов компилируются в сборке Release без `NDEBUG`, поэтому проверки `assert` выполняются; см. [тесты](../dev/tests.ru.md).
- Лаунчер компилируется с `-Os`, а покадровый путь окна — с `-O2`, см. [Release с оптимизацией размера](size-optimized-release.ru.md). Неопределённое поведение проявляется по-разному на разных уровнях оптимизации: переход на `-Os` позволил тестам хоста поймать цикл по уже уничтоженному временному объекту JSON.
- Штатные форматы, которые разбирает лаунчер, приходят из входов с пинами SHA-256, см. [пины](pins.ru.md).

В сборке нет санитайзеров (sanitizers).

## Последствия

Новый код хоста пишется на C++20 по правилу [одной реализации](single-implementation.ru.md); новый код гостя — на C11 и собирается тем же Zig. Библиотеки на C и C++ подключаются без слоя привязок. Безопасность памяти держится на перечисленных проверках и тестах, а не на компиляторе. Rust можно пересмотреть для новой изолированной части хоста с узким интерфейсом на C, например кода разбора нового формата, когда выигрыш перевесит второй закреплённый набор инструментов, или для гостя, когда у Rust появится поддерживаемая цель для QNX 7.0 на aarch64.
