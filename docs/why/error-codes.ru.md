# Коды ошибок и неизвестный исход

## Решение

Код хоста сообщает об отказе через `VoyemuError("CODE", "message")` с текстом `CODE: message`. API превращает `CODE` в верхнем регистре в `error.code`, а CLI сопоставляет ответу код выхода. Код оканчивается на `_UNKNOWN`, только когда результат неудавшейся операции неизвестен, и ровно такие отказы получают `outcome: unknown`; все остальные получают `outcome: not_started`. Исключение без кода получает `FILESYSTEM` или `SYSTEM` по своему виду, в командной строке также `JSON`, а любое другое — `INTERNAL_ERROR` со своим текстом; код не должен прятать за ним известный отказ. API даёт исключению JSON код `TEST_ARGUMENT` до первого обмена с супервизором и `IPC_PROTOCOL` после него, а когда операция уже отправила действие, добавляет к коду такого исключения `_UNKNOWN`.

## Контекст

Клиенты API управляют долго работающими гостями: перезагрузка, нажатие или `flush` могут завершиться ошибкой, когда гость уже выполнил действие. Клиент решает, повторять ли запрос, и ошибка в решении либо повторяет действие, либо бросает то, которое так и не выполнилось.

## Альтернативы

**Отдельное поле исхода, выбираемое в каждом месте выброса.** Код и исход могут разойтись, и при ревью приходится проверять оба в каждом месте.

**Числовые коды ошибок.** В месте выброса они ничего не говорят и требуют таблицы соответствия в каждом клиенте.

**Один общий код для неожиданных отказов.** Клиент теряет сведения, по которым решает о повторе.

## Аргумент

Суффикс делает исход частью имени, поэтому место выброса, ответ JSON и сохранённая квитанция не могут разойтись. Читатель кода видит классификацию там, где происходит отказ. `not_started` сообщает клиенту, что ничего не произошло; `unknown` запрещает автоматический повтор, и клиент проверяет состояние гостя или читает квитанцию через `operation.get`.

## Последствия

Путь отказа, который мог дойти до гостя, требует кода `_UNKNOWN`. Флаг `retryable` задаётся отдельно и только для отказов, где повтор безопасен, например для занятого сеанса или тайм-аута наблюдения, которое только читает состояние. Повтор того же запроса возвращает сохранённую квитанцию, а не выполняет его снова; см. [Voyemu API](api.ru.md). Страница [Ошибки](../how/errors.ru.md) перечисляет поля ошибки и частые коды.
