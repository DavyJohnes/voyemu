# Только Release

## Решение

Собирается только Release. CMake принудительно задаёт `CMAKE_BUILD_TYPE=Release`; файлы наборов инструментов компилируют с `-g0` и удаляют символы при компоновке, поэтому в исполняемых файлах нет отладочной информации и PDB. Отказы разбираются по логам, а не в отладчике.

## Контекст

Сеанс Voyemu минутами держит супервизор, эмулятор, QEMU и двух гостей. Отказы зависят от временных соотношений между этими процессами. Пользователи запускают исполняемый файл из релиза или сборки CI.

## Альтернативы

**Конфигурации Debug и RelWithDebInfo.** Вторая конфигурация удваивает матрицу сборки и тестов и меняет временные соотношения в проверяемом коде. Дефект, который проявляется только в Release, не виден в конфигурации разработчика.

**Release с отдельными файлами символов.** Файлы PDB или dSYM нужно создавать, хранить и сопоставлять с каждым исполняемым файлом. Отладчик, который останавливает супервизор, сам меняет исследуемые временные соотношения.

## Аргумент

Проверяется тот же исполняемый файл, который уходит в релиз. Отказы, зависящие от временных соотношений между процессами, восстанавливаются по упорядоченным записям лога, а не по остановленному процессу. Одна конфигурация делает локальную сборку, CI и релиз одинаковыми.

## Последствия

Каждый путь отказа оставляет в логе достаточно контекста для разбора: если лог не объясняет отказ, нужно больше записей, а не отладочная сборка. Хост пишет структурированные записи лога в JSON в `stderr`. CI проверяет, что сборка Windows не создаёт PDB. Без отладочных секций исполняемые файлы меньше. Настройки компилятора входят в [набор инструментов Zig](zig-toolchain.ru.md). Страница [Логи](../how/logs.ru.md) описывает записи лога и файлы логов сеанса.
