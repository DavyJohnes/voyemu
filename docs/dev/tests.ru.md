# Тесты

Все тесты запускаются через CTest из дерева сборки, настроенного с `BUILD_TESTING=ON`, см. [сборку](build.ru.md). Тесты проверяют поведение: они выполняют код и сравнивают результаты, но никогда не читают исходники и не закрепляют файлы репозитория хешем; см. [тесты проверяют поведение](../why/behavior-tests.ru.md).

```sh
ctest --test-dir .local/build/native --output-on-failure --parallel 1
```

Для теста ограждений запуска Windows на POSIX нужен KornShell. По умолчанию используется `/bin/ksh`; путь к пользовательской установке задаёт переменная `VOYEMU_TEST_KSH`. Неверный явно заданный путь приводит к ошибке теста; отсутствие оболочки по умолчанию пропускает выполнение ограждений. Linux CI распаковывает закреплённый пакет Ubuntu KornShell в `.local/toolchains` и задаёт эту переменную для CTest.

## Тесты C и C++

Тест C++ лежит рядом с проверяемым кодом как `<name>.test.cpp`, например `src/app/api/api.test.cpp` рядом с `api.cpp`. Для каждого зарегистрированного имени CMake находит ровно один соседний исходник теста, иначе настройка завершается ошибкой. Тесты гостевого кода на C лежат рядом с ним в `src/guest/qnx/` как `<name>.test.c`. Двойники гостевых интерфейсов, например `guest_android_fake.hpp`, лежат рядом с интерфейсом, который заменяют.

Исполняемые файлы тестов собираются в той же конфигурации Release, что и продукт, но с включёнными проверками: каждая цель с именем на `_test` компилируется без `NDEBUG`, поэтому проверки `assert` выполняются.

## Регистрация и метки

Каждый тест регистрируется через `voyemu_add_test` в `src/app/CMakeLists.txt`; метки и тайм-аут в секундах обязательны, а для теста, зарегистрированного иначе, настройка завершается ошибкой.

```cmake
voyemu_add_test(update_image LABELS deps TIMEOUT 60 COMMAND update_image_test "${voyemu_project_root}")
```

| Метка | Тесту нужны |
| --- | --- |
| `host` | Только дерево сборки и закреплённые инструменты сборки, включая JDK |
| `deps` | Инструменты, которые устанавливает `deps`, например Android SDK, библиотеки Java или кодек обновлений QNX |
| `oem` | Импортированные оригиналы |

Тесты выбираются по меткам через `ctest --label-regex` и `--label-exclude`; [CI](ci.ru.md) запускает в нативных заданиях Linux, macOS и Windows только слой хоста без меток `oem` и `deps`:

```sh
ctest --test-dir .local/build/linux --label-exclude 'oem|deps' --output-on-failure
```

## Тесты Java

Задание `source-fixtures` в [CI](ci.ru.md) запускает общедоступные проверки поведения Java и передачу нативных компонентов на Linux, macOS и Windows. Действие установки закреплённых инструментов скачивает библиотеки Java, Android 34, Build Tools 36.1.0, NDK 29 и его CMake/Ninja по URL и SHA-256 из репозитория; пока ресурсы релиза не опубликованы, проверка передачи собирает нативные компоненты Free 6.0.3 по рецепту этим NDK. Инструменты скачиваются отдельно от команды `fetch`, которая импортирует оригиналы; установка эмулятора и сборка QEMU не нужны. Задание явно исключает `oem`, и все выбранные наборы должны пройти без пропусков. Гостевой код на Java компилируется с `--release 8` тем же закреплённым JDK 25, который запускает тесты хоста.

`passion_carsettings_source`, `canbus_source` и `prepare_java_android_stubs_source` явно выбирают собственные тестовые данные репозитория через `TEST_OEM=OFF`. Отдельные наборы `_oem` выбирают `TEST_OEM=ON` и требуют импортированные APK CarSettings/Multimedia/Camera для Passion, оригиналы QGAPI/Launcher для Free 7.3.1 либо донорские APK компонента CanBus для Free 6.0.3, 6.11.1 и 7.3.1, которые нужны их проверкам. Без оригиналов эти наборы завершаются ошибкой; общедоступное задание исключает их по метке `oem`.

Тесты Java лежат в `src/prepare/test/`:

| Каталог | Содержимое |
| --- | --- |
| `java/com/voyemu/prepare/` | Тесты отдельных классов инструментов подготовки |
| `java/host-unit/` | Запуск через CTest классов Java, которым нужны только исходники |
| `java/android-stubs/` | Тесты гостевого кода Java на двойниках Android для JVM |
| `java/oem/` | Тесты рецептов по группам профилей, которым нужны оригиналы |
| `java/guest-units/` | Запуск через CTest тестов `src/guest/android/api/` и гостевых компонентов с двойниками Android для JVM в `host-tests/` |
| Остальные каталоги | Сценарные тесты одного рецепта или компонента, у каждого свой `run.cmake` или `run.sh` |

Тесты Java работают на закреплённом JDK хоста; `VOYEMU_JDK` задаёт другой каталог JDK.

## Тесты, которым нужны входы

Некоторые прежние тесты, которым нужны оригиналы, настоящая сборка ANGLE или другие закреплённые входы, завершаются с кодом `77`, если этих входов нет, и CTest отмечает их пропущенными. Строгие тесты телефона, передачи нативных компонентов и Settings Free 7.3.1 без входов завершаются ошибкой; выбор по меткам не меняет их поведение. Прежние скрипты тестов CMake с пропуском завершаются через `cmake_language(EXIT 77)`. Пропуск — не успех: отчёт о проверках называет каждый пропуск и его причину. Тесты хоста не заменяют приёмку сценария гостя на запущенной машине.

## Временные файлы

Тесты пишут временные файлы в `.local/build/tmp/` или в дерево сборки и никогда — в дерево исходников.
