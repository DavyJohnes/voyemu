# Проверки

Статические проверки запускаются перед каждым коммитом и в [CI](ci.ru.md). Каждая проверка использует закреплённый инструмент, а настройки инструментов лежат в `config/`. Каждое замечание исправляют или подавляют комментарием с причиной.

| Проверка | Команда | Инструмент и настройка |
| --- | --- | --- |
| Форматирование и Checkstyle | `cmake --build .local/build/native --target format-check` | clang-format 23.1.3 с `config/config-clang-format.yaml`, Uncrustify 0.83.0 с `config/config-uncrustify.cfg`, `src/dev/format/JavaBlankLines.java`, google-java-format 2.0.0 в стиле AOSP, Checkstyle 12.3.1 с `config/config-checkstyle.xml` |
| clang-tidy | `cmake --build .local/build/native --target tidy-check` | clang-tidy 23.1.3 с `config/config-clang-tidy.yaml` |
| Error Prone | `cmake --build .local/build/native --target errorprone-check` | Error Prone 2.52.0 на закреплённом JDK |
| EditorConfig | `java src/dev/checks/EditorConfigCheck.java .` | Окончания строк, финальный перевод строки, пробелы в конце строк и отступы по `config/config-editor` |
| Документация | `java src/dev/checks/CheckDocs.java .` | Пары страниц, ссылки, термины глоссария и записи о решениях |

## lint и lint-fix

`lint` запускает все проверки из таблицы, не меняя файлы; его запускает [CI](ci.ru.md). `lint-fix` — локальная команда перед коммитом: она применяет все автоматические исправления, затем запускает `lint`, который завершается ошибкой, если замечания остались. Их разработчик исправляет вручную.

```sh
cmake --build .local/build/native --target lint-fix
cmake --build .local/build/native --target lint
```

`lint-fix` сначала запускает `tidy-fix`: он применяет исправления тех проверок clang-tidy, которые лишь переписывают тот же код, — фигурные скобки вокруг операторов, `else` после `return`, лишние переходы, `nullptr` и `override`. Исправления проверок `bugprone` меняют поведение, поэтому их вносят вручную. Затем `lint-fix` запускает цель `format`, которая заодно форматирует исправления clang-tidy. `lint-fix` выполняет свои шаги через `cmake --build`; `CMAKE_BUILD_PARALLEL_LEVEL` ограничивает их параллельные задания.

## Форматирование и Checkstyle

`format-check` проверяет исходники C, C++ и Objective-C++ в `src/app/`, `src/dev/` и `src/guest/` и исходники Java в `src/prepare/`, `src/guest/` и `profiles/`, затем запускает Checkstyle на исходниках Java. Пустые строки отделяют управляющие конструкции (`if`, `for`, `while`, `do`, `switch` и `synchronized`) от соседних операторов. Они стоят после всей конструкции `try` с её обработчиками, а в Java — и перед ней; кроме того, перед `return`, если он не первый в блоке, и после объявлений в начале функции. Эти строки расставляет Uncrustify между двумя проходами clang-format, а в Java — `JavaBlankLines.java` перед google-java-format. Одна пустая строка также отделяет определения функций и методов друг от друга и от объявлений и другого кода вокруг них в области файла, пространства имён и класса: комментарий прямо над определением остаётся при нём, подряд идущие объявления не разделяются, а тело пространства имён или `extern "C"` не начинается и не заканчивается пустой строкой. google-java-format так же разделяет методы Java. Перед проверкой дерева цель запускает `src/dev/format/format.test.cmake` на тестовых данных из `src/dev/format/test/`: режим проверки должен отклонить каждый неотформатированный файл, а режим исправления — превратить его в копию `.formatted`, которую режим проверки затем принимает. `cmake -P src/dev/format/uncrustify.cmake` устанавливает закреплённый Uncrustify: скачивает исполняемый файл для хоста, который собирает [рабочий процесс uncrustify](ci.ru.md#рабочий-процесс-uncrustify), и сверяет его SHA-256. С `-DVOYEMU_UNCRUSTIFY_FROM_SOURCE=ON` он вместо этого собирает Uncrustify из закреплённого архива релиза закреплённым Zig и сверяет результат с тем же пином; Python 3 нужен только такой сборке. Закреплённый сторонний код, сгенерированные файлы и тестовые данные форматирования исключены. Цель `format` не проверяет файлы, а переписывает их. Скрипту не нужно дерево сборки:

```sh
cmake -DVOYEMU_FORMAT_MODE=check -P src/dev/format/format.cmake
```

## clang-tidy

`tidy-check` сначала собирает все проверяемые цели, чтобы появились сгенерированные заголовки, затем запускает clang-tidy на каждом исходнике Voyemu на C, C++ и Objective-C++ из дерева сборки через `compile_commands.json`. Компоненты профилей и закреплённый сторонний код в проверку не входят. `VOYEMU_TIDY_JOBS` ограничивает число параллельных процессов, по умолчанию 4. Проверка нужна в дереве сборки каждой целевой платформы: каждое дерево компилирует свои платформенные части.

## Error Prone

`errorprone-check` компилирует с Error Prone инструменты подготовки и их тесты, гостевой код Java и тесты, которые запускают гостевой код Java на двойниках Android для JVM; любое предупреждение Error Prone или javac считается ошибкой проверки. Ей нужны закреплённые библиотеки Java, D8 и apksigner. Скрипт тоже работает без дерева сборки:

```sh
cmake -P src/app/errorprone.cmake
```

## Проверка EditorConfig

`EditorConfigCheck` проверяет каждый отслеживаемый текстовый файл по `config/config-editor`: окончание строк, ровно один финальный перевод строки, отсутствие пробелов в конце строк и пробелы в начальных отступах. Файлы с байтами NUL считаются двоичными и пропускаются.

## Проверка документации

`CheckDocs` проверяет `docs/` и корневые пары `README`, `CHANGELOG`, `SECURITY` и `CONTRIBUTING`: у каждой страницы есть английский и русский файл с одинаковой структурой заголовков, таблиц и блоков кода. Каждая страница документации достижима по ссылкам из `docs/index.md`, а русская — из `docs/index.ru.md`; эти ссылки задают порядок чтения, в котором сайт Voyemu публикует документацию. Ссылки и якоря должны разрешаться, записи о решениях — содержать свои пять разделов, а в прозе не должно быть запрещённых вариантов из глоссария, эмодзи и внутренних меток. При любом замечании проверка завершается с ненулевым кодом.

```sh
java src/dev/checks/CheckDocs.java
```

Пути инструментов по умолчанию берутся из пинов в `src/app/toolchain.json`; `VOYEMU_CLANG_FORMAT`, `VOYEMU_GOOGLE_JAVA_FORMAT` и `VOYEMU_CLANG_TIDY` задают другие исполняемые файлы той же версии.
