# free-11-chinese-20260731-7.3.1

The Chinese Free firmware 7.3.1 of 31 July 2026 on Android 11. The profile is supported with both subsystems: the multimedia and the cluster.

## Guests

| Item | Value |
| --- | --- |
| Android | 11, API 30, arm64 system image |
| Emulator memory | 4096 MiB |
| Cluster | QNX with the `sa8155-qinggan11-731` hardware adapter |
| Steering wheel | `free-2024` |
| Development kernel | `qinggan-11` |

## OEM inputs

Import the pinned inner firmware archive `update.zip` from an absolute local path. Neither the outer archive `731.zip` nor `update-mcu.zip` is needed. `fetch` extracts the Android and QNX images it needs from `update.zip`. Preparation takes the `su` rules of the Android machine from the SELinux policies of the system_ext and vendor partitions, so `su` is restricted as in the vehicle.

```sh
./voyemu deps free-11-chinese-20260731-7.3.1
./voyemu fetch free-11-chinese-20260731-7.3.1 --source=/absolute/path/update.zip
./voyemu build free-11-chinese-20260731-7.3.1
```

## Notes

`build free-11-chinese-20260731-7.3.1 --cluster=off --multimedia=on` into an existing stopped machine updates only its Android system and keeps the writable disks and the cluster, see [preparation](../how/preparation.md).

The rear-seat screen of the vehicle, 1902×540, is the third Android display; the [screens window](../how/window.md#screens) shows it. Preparation imports the OEM rear-screen application `/vendor/app/ThirdScreen-release-signed/ThirdScreen-release-signed.apk` and starts its home on the rear display found by its unique ID, and the screen plays `/system/media/bootanimation2.zip` until Android is ready. The rear screen never delays the readiness of the multimedia screens. The profile keeps `persist.app.kuwo.support` off, so the application shows its music without Kuwo.

The machine runs the OEM `SystemPolicy` and `QGBus` imported from the firmware; they deliver media, phone and navigation data over the [cluster data channel](../how/vehicle.md#cluster-data-channel).
