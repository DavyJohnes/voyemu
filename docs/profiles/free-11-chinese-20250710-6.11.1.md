# free-11-chinese-20250710-6.11.1

The Chinese Free firmware 6.11.1 of 10 July 2025 on Android 11. The profile is supported with both subsystems: the multimedia and the cluster.

## Guests

| Item | Value |
| --- | --- |
| Android | 11, API 30, arm64 system image |
| Emulator memory | 4096 MiB |
| Cluster | QNX with the `sa8155-qinggan11-611` hardware adapter |
| Steering wheel | `free-2024` |
| Development kernel | `qinggan-11` |

## OEM inputs

Import the pinned firmware archive `update.zip` from a local path; `fetch` extracts the Android and QNX images it needs. Authorized ADB with the pinned SDK `adb` can import the Android files declared in `profile.json` from a physical vehicle, but does not supply the QNX originals: those require the firmware archive or already imported QNX images. The firmware's `update-mcu.zip` is not needed. Preparation takes the `su` rules of the Android machine from the SELinux policies of the system_ext and vendor partitions, so `su` is restricted as in the vehicle.

```sh
./voyemu deps free-11-chinese-20250710-6.11.1
./voyemu fetch free-11-chinese-20250710-6.11.1 --source=path/to/update.zip
./voyemu build free-11-chinese-20250710-6.11.1
```

To import Android files from the vehicle after obtaining the QNX originals, run `./voyemu fetch free-11-chinese-20250710-6.11.1 --source=adb --serial SERIAL`. This does not replace the firmware-archive import on a clean installation.

## Notes

The cluster adapter of this profile writes the fields of the [vehicle model](../how/vehicle.md) into the OEM MCU packet as the adapter of Free 7.3.1 does; `vehicle.fields` lists the guests of each field, and the window grays out the controls of fields that reach neither guest as a profile limit.

The rear-seat screen of the vehicle, 1902×540, is the third Android display; the [screens window](../how/window.md#screens) shows it. Preparation imports the OEM rear-screen application `/vendor/app/ThirdScreen-release-signed/ThirdScreen-release-signed.apk` and starts its home on the rear display found by its unique ID, and the screen plays `/system/media/bootanimation2.zip` until Android is ready. The rear screen never delays the readiness of the multimedia screens. The profile keeps `persist.app.kuwo.support` off, so the application shows its music without Kuwo.

As in the vehicle, the emulated NVRAM declares the vehicle type H97C, and the application list shows the tiles of this type. The tiles Karaoke, VoiceGame and Schedule stay hidden because the machine has no applications behind them.

The machine runs the OEM `SystemPolicy` and `QGBus` imported from the firmware; they deliver media, phone and navigation data over the [cluster data channel](../how/vehicle.md#cluster-data-channel).

The Camera tile opens the ordinary camera and the DVR tile the OEM DVR application, both with a virtual camera, see [camera and DVR](../how/camera.md).

The Video tile opens the OEM Video application `com.qinggan.app.video`; preparation adds to it the same pinned ARM64 libraries as to the OEM Gallery, so the application runs on ARM64 hosts without 32-bit support.
