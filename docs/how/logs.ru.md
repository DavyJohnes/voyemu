# Логи

Voyemu собирается только в Release и без отладочных символов, поэтому инструмент диагностики — логи; см. [только Release](../why/release-only.ru.md). Хост пишет структурированные записи, а каждый сеанс хранит в файлах вывод своих гостей и вспомогательных процессов.

## Записи хоста

У каждой записи хоста одни и те же поля:

| Поле | Содержимое |
| --- | --- |
| `schemaVersion` | Версия формата записи, `1` |
| `sequence` | Возрастающий номер внутри процесса |
| `timestamp` | Время UTC с миллисекундами |
| `source` | `{"kind":"host","id":"voyemu"}` |
| `level` | `error`, `info` или `debug` |
| `component` | Часть Voyemu, создавшая запись |
| `message` | Событие |
| `fields` | Структурированные значения события |

Обычные команды записи не выводят: в консоли видны только шаги, прогресс, итог и ошибки. `voyemu test` и супервизор выводят в `stderr` по одной JSON-записи на строку, чтобы `stdout` оставался за результатом.

## Лог команды

Все команды, кроме `check`, `help`, `--version` и `test`, пишут свои записи в новый файл `.local/build/logs/<command>-<YYYYMMDD-HHMMSS>.log` с местным временем запуска, по одной JSON-записи на строку, включая отладочные; см. [корни `.local`](local-roots.ru.md). Остаются 20 самых новых логов, более старые удаляет следующая команда. Неудачная или прерванная команда выводит путь к своему логу последней строкой, успешная — нет. Ошибка без локализованного текста выводит только код и путь к логу, а лог хранит полное английское сообщение — его и нужно приложить к сообщению о проблеме. `check` только читает установку и лога не ведёт, поэтому выводит такую ошибку целиком.

`--verbose` у `deps`, `fetch`, `build`, `start` и `restart` дополнительно выводит в `stderr` записи `info` и `error` текстом: компонент, сообщение и простые поля в виде `key=value`.

## Отладочный уровень

Отладочные записи всегда попадают в лог команды. В `stderr` они по умолчанию выключены; `VOYEMU_LOG_LEVEL=debug` в окружении включает их для `--verbose`, `voyemu test` и супервизора.

```sh
VOYEMU_LOG_LEVEL=debug ./voyemu start machines/free-09-chinese-20260106-6.0.3 --verbose
```

## Файлы логов сеанса

У каждого сеанса есть каталог `.local/machines/<name>/sessions/<id>/`, см. [корни `.local`](local-roots.ru.md). В нём, среди прочего, лежат:

| Файл | Источник |
| --- | --- |
| `android.log` | Процесс Android Emulator |
| `qnx-console.log` | Процесс QEMU приборки |
| `qnx-serial.log` | Последовательная консоль QNX |
| `graphics-*.log` | Графический обработчик |

Когда приборка перезапускается внутри сеанса, её логи и файлы кадров переезжают в `cluster-history/<generation>/`, так что у каждого поколения свои логи.

## Логи через API

`session.logs` читает диагностику работающего сеанса. Поле `source` выбирает источник: `supervisor` (по умолчанию) возвращает события супервизора с курсором для чтения по частям; `android` возвращает снимок логов Android, с `details: true` — подробнее; `anr` и `native` возвращают последнюю трассировку ANR Android и последний отчёт о нативном сбое.
