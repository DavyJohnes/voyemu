# Ошибки

У каждой ошибки Voyemu есть код в верхнем регистре и сообщение, записанные как `CODE: message`. Код сообщает клиенту, что не удалось и могла ли операция что-то изменить. Правило, на котором это держится, — в записи [коды ошибок и неизвестный исход](../why/error-codes.ru.md).

## Объект ошибки

Неудачный ответ [Voyemu API](api.ru.md) содержит `ok: false` и объект `error`:

```json
{"schema":1,"request_id":"tap-1","ok":false,"error":{"code":"TEST_BUSY","message":"another automation writer or capture is active","retryable":true,"outcome":"not_started"}}
```

| Поле | Значение |
| --- | --- |
| `code` | Код в верхнем регистре до двоеточия |
| `message` | Текст после двоеточия, не больше 1024 байт |
| `retryable` | `true` только там, где повтор запроса безопасен |
| `outcome` | `not_started` или `unknown` |
| `details` | Необязательно; ошибки ввода и идентичности машины добавляют структурированные подробности |

## Исход

Код с окончанием `_UNKNOWN` значит, что результат операции неизвестен: гость мог уже выполнить действие, например после отправленной перезагрузки или `flush`. Только у таких ошибок `outcome: unknown`, и клиент должен проверить состояние гостя или прочитать квитанцию через `operation.get`, а не повторять действие. У всех остальных ошибок `outcome: not_started`: ничего не произошло, и можно отправить исправленный запрос.

## Ошибки, допускающие повтор

`retryable` задаётся только там, где повтор не может вызвать второго действия:

| Код | Ситуация |
| --- | --- |
| `TEST_BUSY` | Уже выполняется другая изменяющая операция автоматизации или снимок экрана |
| `CLUSTER_UI_NOT_READY` | Приборку пока нельзя наблюдать |
| `TREE_TIMEOUT`, `TREE_TIMEOUT_UNKNOWN`, `TREE_TRANSPORT_UNKNOWN` | У чтения дерева UI истёк тайм-аут, или оно потеряло транспорт |
| `CAN_TIMEOUT`, `CAN_TIMEOUT_UNKNOWN`, `CAN_TRANSPORT_UNKNOWN` | У чтения CAN истёк тайм-аут, или оно потеряло транспорт |

## Частые коды

| Код | Значение |
| --- | --- |
| `TEST_SCHEMA` | Запрос — не объект со `schema: 1` |
| `TEST_ARGUMENT` | Поле отсутствует, искажено или вне диапазона; сюда же относится запрос с испорченным JSON или неверной структурой |
| `TEST_UNSUPPORTED` | Неизвестная операция или возможность, которой нет у этой машины |
| `TEST_SESSION` | Неверный ID сеанса, либо сеанс неизвестен, неоднозначен, остановлен или изменился |
| `TEST_OWNERSHIP` | Запрос меняет сеанс без владения |
| `REQUEST_CONFLICT` | `request_id` уже использован с другим содержимым |
| `PROFILE_NOT_PREPARED` | У выбранной машины нет подготовленной настройки запуска |
| `FILESYSTEM` | Файловая операция не выполнена; сообщение называет операцию, путь и причину от системы |
| `SYSTEM` | Другой системный вызов не выполнен; сообщение называет причину |
| `INTERNAL_ERROR` | Непредвиденный сбой без кода; сообщение сохраняет его текст |
| `IPC_PROTOCOL` | Ответ супервизора — испорченный JSON или имеет неверную структуру |

Код хоста никогда не прячет известный сбой за `INTERNAL_ERROR`. Испорченный JSON, который код хоста читает сам, в командной строке даёт `JSON`. Коды других областей, например `FETCH_MISSING` для отсутствующих оригиналов или `CLI_COMMAND` для неизвестной команды, следуют тому же формату.

## Командная строка

Команды, кроме `test`, выводят ошибку текстом в `stderr`, `Voyemu: CODE: message`, и завершаются с кодом `4`. Команда, прерванная по Ctrl+C, останавливается в ближайшей безопасной точке, удаляет незавершённые загрузки и временные файлы, выводит `Voyemu: INTERRUPTED: команда прервана.` и завершается с кодом `130`. `test` всегда выводит JSON-ответ в `stdout`, даже если запрос не удалось прочитать; его коды завершения перечислены в [Voyemu API](api.ru.md).
