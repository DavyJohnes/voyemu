# Встроенный ADB

Супервизор общается с гостем Android своего сеанса через собственный клиент ADB, встроенный в лаунчер. Клиент подключается по локальному адресу к конечной точке `adbd` того эмулятора, который запустил этот сеанс, и не использует сервер ADB, общий с другими программами. Причины — в записи [встроенный ADB](../why/embedded-adb.ru.md).

## Что через него проходит

Команды оболочки и долгие потоки оболочки, которые сеанс запускает внутри Android, идут через этот транспорт; перед каждым использованием супервизор проверяет, что процесс эмулятора и поколение гостя всё ещё принадлежат ему. Запуск подготовленной машины всегда выбирает встроенный транспорт.

## Владение

Один процесс супервизора владеет одним транспортом эмулятора. Перед подключением супервизор проверяет, что конечная точка принадлежит запущенному им процессу эмулятора, его консоли и слушателю `adbd`, поэтому другой эмулятор на том же хосте не ответит за гостя. После тёплой перезагрузки клиент открывает новое соединение с гостем нового поколения.

## Где остаётся adb из SDK

Подготовка машины и импорт с физического автомобиля через `fetch PROFILE --source=adb --serial SERIAL` используют закреплённый `adb` из Platform Tools. Транспорта USB у встроенного клиента нет.

Клиент состоит из кода Voyemu в `src/app/adb/` и исходников ADB из AOSP в `src/app/third_party/aosp_adb/`; CMake сверяет неизменённые файлы AOSP с их пинами перед сборкой.
